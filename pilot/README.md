# Пилот: кликабельные выноски на чертеже

Проверка на практике идеи из `docs/research_clickable_callouts.md` — можно ли
сделать номера-выноски на чертеже кликабельными (клик по номеру ↔ подсветка
строки спецификации), и с какой точностью/ценой это делает vision-модель.

**Демо:** откройте `pilot_callouts.html` двойным кликом в браузере (1.8 МБ,
самодостаточный). Слева — 13 листов, справа — чертёж с оранжевыми клик-точками
поверх выносок + связанная таблица. Наведение/клик по точке ↔ строка
подсвечиваются взаимно.

## Итог пилота

| Показатель | Значение |
|---|---|
| Листов обработано | 13 (спред по плотности: от 2 до 35 выносок, все 3 каталога) |
| Выносок всего | 146 |
| Локализовано автоматически (vision) | **142 (97 %)** |
| Промахи | 4 — все на одном листе (wp17_p065: плотный разнесённый вид + водяные знаки, 24/28) |

Метод: координаты каждой выноски определены vision-моделью по картинке (без
OCR — классический CV на тесте давал мусор). Задача ограничена и проверяема:
набор ожидаемых позиций на листе уже известен из распарсенной таблицы.

## Что подтвердилось

- **Чистые чертежи с кружками-выносками** (большинство БС): ~100 %. Точки
  садятся ровно на нарисованные кружки.
- **Плотные схемы с выравненными номерами** (ШУ1, 35 выносок): все 35 найдены;
  у тесно-стоящих в столбик точность центра ниже — точки чуть перекрываются,
  но каждая на своей цели.
- **WP17-стиль без кружков** (мелкие цифры на концах линий): читаемо, но это
  самый сложный случай; на плотном разнесённом виде с водяными знаками
  (wp17_p065) — 86 %, часть цифр сливается с графикой → нужна ручная правка.
- **Важно: не на каждом изображении есть выноски.** 2 из 13 листов начинались
  с «общего вида» без выносок (Ключ, Установка насосная) — выноски были на
  следующем, детальном изображении того же листа. Значит, обрабатывать нужно
  **каждое** изображение (их 695, а не 470 листов), и общие виды корректно
  получают ноль выносок.

## Оценка на полный объём (уточнённая пилотом)

- Обрабатывать **695 изображений-чертежей** (а не 470 листов — из-за общих видов).
- ~2000 токенов на изображение (картинка + запрос + JSON-ответ) → ~1.4 млн один проход.
- Проверка/повтор по ~15–20 % (плотные/бледные) + оркестрация/тесты → **итого ~1.6–2.2 млн токенов, разово.**
- Совпадает с прогнозом из исследования (1.5–2.5 млн). Клики пользователей потом бесплатны.

**Точность на полном объёме:** ожидаемо ~90–97 % автоматически; ~18 самых
плотных листов (21–42 выноски) и разнесённые виды WP17 с водяными знаками —
с выборочной ручной правкой.

## Файлы

- `pilot_callouts.html` — интерактивное демо (самодостаточное).
- `pilot_coords.json` — координаты выносок (нормированные x,y) по каждому изображению.
- `build_pilot_demo.py` — сборка данных демо (позиции + координаты + встроенные картинки).
- `gen_pilot_html.py` — генерация HTML демо.

## Как встроить в основной каталог (если делать полный прогон)

Координаты (нормированные x,y на позицию) добавляются в `data.js` рядом с
каждой строкой; в `viewer.html` поверх `.figcar img` рисуется слой
абсолютно-позиционированных клик-зон (как в демо), с взаимной подсветкой
«точка ↔ строка таблицы». Данные статичны — на рантайме токенов не тратят.
