# Исследование: кликабельный выбор детали прямо на чертеже (по номеру-выноске)

**Вопрос:** можно ли сделать так, чтобы клик по номеру-выноске (1, 2, 3…),
нарисованному на чертеже, выбирал/подсвечивал соответствующую строку в
спецификации (и наоборот). Сколько это стоит в токенах.

**Короткий ответ:** технически возможно, но не «бесплатно» и не на 100 %
автоматически. Единственный надёжный способ найти координаты выносок —
vision-модель. Ориентировочная стоимость обработки всех трёх каталогов —
**~1.5–2.5 млн токенов, разово** (не на каждого пользователя). После обработки
координаты сохраняются в данные, и клики пользователей токенов не тратят.

---

## Что проверено (факты, а не предположения)

### 1. Выноски на чертежах — это растр, а не текст PDF
Проверены все три каталога. На «чистых» страницах-чертежах извлекаемого
текста с числами практически нет (≈1 числовой токен на страницу — это номер
страницы). Все номера-выноски «впечатаны» в картинку. То есть **дешёвый путь
«достать координаты цифр из текстового слоя PDF» недоступен** ни в одном из
каталогов (в т.ч. WP17 — там числа лежат только в области таблицы под
чертежом, не на самом чертеже).

### 2. Векторных кружков/линий-выносок в PDF тоже нет
`get_drawings()` на страницах-чертежах возвращает только прямоугольники
(сетку таблицы). Сам чертёж — включая кружки выносок и линии-указатели —
целиком внутри растрового изображения. Значит, найти кружки «по геометрии
PDF» нельзя.

### 3. Классический компьютерный CV (без токенов) — не работает «из коробки»
Проверено на реальном чертеже: поиск кружков (Hough Circles, OpenCV) +
распознавание цифры в каждом кружке (Tesseract OCR). Результат:
- найдено 95 «кружков-кандидатов», но большинство — ложные (элементы 3D-модели);
- OCR внутри кружков вернул мусор (сплошные «0» вместо реальных 1–7).

Вывод: классический CV потребовал бы серьёзной ручной настройки **под каждый
стиль чертежа отдельно** и всё равно давал бы низкую точность. Как основной
путь не годится. (Тем не менее это единственный путь с нулём токенов —
см. «Варианты».)

### 4. Vision-модель — читает выноски уверенно
Проверено вручную на детальном чертеже с 7 выносками: все кружки-номера
(1–4 в ряд, 5–7 столбиком) читаются чётко, центр каждого можно указать с
точностью в несколько процентов. Для клик-зоны этого достаточно — хот-спот
садится прямо на кружок с номером, точность «попасть в цель» ±20 px не
критична.

---

## Масштаб задачи (из уже распарсенных данных)

| Показатель | Значение |
|---|---|
| Листов-чертежей со спецификацией | 470 |
| Всего изображений-чертежей | 695 |
| Всего выносок для локализации | 4067 |
| Плотность: 1–5 выносок / лист | 193 листа |
| 6–10 / лист | 155 |
| 11–20 / лист | 117 |
| 21–42 / лист (сложные) | 18 |

## Почему это выполнимо и даже проще, чем кажется

Задача для vision-модели **ограничена и проверяема**: мы уже точно знаем, какие
номера позиций есть на каждом листе (из распарсенной таблицы — например, «на
этом листе позиции 1–7»). Поэтому запрос к модели не «найди что-нибудь», а
«найди на картинке вот эти конкретные N номеров и верни координату центра
каждого». Результат можно автоматически сверить: вернулись ровно ожидаемые
номера — принято; чего-то не хватает или дубли — переспросить только этот лист.

---

## Оценка стоимости (токены)

Разовая обработка, на стороне генерации (не на пользователе):

**На один чертёж:**
- картинка на вход vision-модели: ~1600 токенов (страница, сжатая до ~1568 px);
- инструкция + список ожидаемых номеров: ~200 токенов;
- ответ (JSON с координатами): ~130–600 токенов (в среднем ~200).
- **Итого ≈ 2000 токенов на чертёж.**

**Полный прогон (≈500 чертежей с выносками):**
- один проход: ~1.0 млн токенов;
- авто-проверка + повторный проход по ~25–35 % листов (плотные/бледные): +~0.35 млн;
- оркестрация, запись координат в данные, тестирование: +~0.2–0.4 млн.
- **Реалистично: ~1.5–2.5 млн токенов, разово.**

По деньгам это единицы–десятки долларов токенов, один раз. После обработки
координаты выносок сохраняются в `data.js` рядом со спецификацией; интерфейс
рисует прозрачные клик-зоны поверх картинки — **клики пользователей токенов
не тратят вообще.**

## Ожидаемая точность

- ~90–95 % выносок ставятся верно автоматически (чистые кружки — большинство);
- 18 очень плотных листов (21–42 выноски) и отдельные бледные — потребуют
  выборочной ручной правки;
- **не 100 % «под ключ»** — заложите немного ручной проверки.

---

## Варианты по стоимости

1. **Полный vision-проход** (~1.5–2.5 млн токенов) — все 470 листов кликабельны
   на чертеже. Максимальный результат, разовая цена.
2. **Только приоритетные узлы** — обработать не всё, а, например, самые
   ходовые узлы/оборудование. Токены пропорционально меньше.
3. **Классический CV, 0 токенов** — не рекомендую: как показал тест, без
   тяжёлой настройки под каждый стиль даёт мусор и низкую точность.
4. **Ничего не делать (уже есть в каталоге)** — связка «клик по строке
   таблицы ↔ чертёж» уже работает: строка подсвечивается, чертёж
   увеличивается, номер позиции в кружке (как на чертеже) виден в таблице.
   Именно так устроен и референсный каталог NHL/«Развитие» — там выноски на
   чертеже тоже **не** кликабельны. То есть on-drawing хот-спот — это приятное
   улучшение, а не отсутствующая базовая функция.

## Рекомендация

Если цель — «чтобы можно было тыкать по цифре на чертеже» — это делается
vision-проходом за ~1.5–2.5 млн токенов разово, с выборочной ручной правкой
плотных листов. Прежде чем запускать на всех 470 листах, разумно сделать
**пилот на 10–15 листах** (~30–50 тыс. токенов): отладить формат запроса и
клик-зон, увидеть реальную точность и итоговую цифру, и уже потом решать —
гнать полный прогон, ограничиться приоритетными узлами или оставить текущую
связку «таблица ↔ чертёж».
