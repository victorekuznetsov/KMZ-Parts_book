# KMZ-Parts_book

Заводские каталоги запасных частей и **генератор интерактивных каталогов** из PDF.
Брендировано под АО «Развитие» (контрагент АО «Копейский машзавод» по этим
каталогам) — цвета/лого в `tools/viewer.html`, легко перебрендировать под
другую компанию (см. CSS-переменные в начале файла).

Из PDF-каталога (страницы «чертёж + таблица спецификации») собирается офлайн-сайт:
чертежи рядом со спецификациями (№ · Номер детали · Наименование · Цена ·
Кол-во · Нужно), сквозной поиск детали, зум чертежей (карусель для листов с
несколькими изображениями), заказ с ценами и итоговой суммой, экспорт в CSV/Excel.

**`catalog_book/index.html` — единственный файл, полностью самодостаточный**
(все чертежи встроены внутрь как data:-URI). Открывается двойным кликом в
любом браузере после простого `git clone`/скачивания репозитория с GitHub —
никаких соседних папок, никакого Python на стороне читателя. Python нужен
только для *сборки* каталога из PDF.

## Быстрый старт (сборка/добавление каталога)

```bash
pip install pymupdf

# добавить каталог (PDF, ZIP или разбитый ZIP.001 — части найдутся сами)
python3 tools/build_catalog.py "Новый каталог.pdf" --id new1 --label "НОВЫЙ" \
        --title "Полное название оборудования" --sub "Обозначение документа"

# результат: catalog_book/index.html — сразу самодостаточный, готов к раздаче
```

Повторный запуск с новым файлом **добавляет** его к уже собранному каталогу.
Неизменённые источники пропускаются по кэшу (SHA1), пересборка — мгновенная.
Чертежи встраиваются в `index.html` автоматически при каждой сборке — не
нужно помнить про отдельный шаг «упаковки», результат всегда готов к commit/раздаче.

Для быстрой локальной разработки (когда чертежей много и не хочется ждать
base64-кодирование при каждом запуске) есть флаг `--no-embed`: `index.html`
тогда лишь ссылается на `data.js`/`img/` рядом — такой файл **не для
распространения**, перед коммитом/отправкой пересоберите без флага.

## Прайс-лист (цены в каталоге)

```bash
python3 tools/apply_prices.py "Прайс-лист.xlsx"   # вписывает цены в кэш .build/*.json
python3 tools/build_catalog.py "<тот же PDF>" --id <тот же id>  # кэш-хит, пересобрать index.html с ценами
```

Номера деталей у КМЗ — 17-18-значные; Excel хранит числа с точностью ~15-16
значащих цифр, поэтому колонка «Номенклатурный номер» в прайс-листе **уже
теряет точность в самом файле** (проверяется по сырому XML, не чинится
перепарсингом). Слепое сопоставление по округлённому числу даёт ~79% ложных
совпадений. `apply_prices.py` поэтому сопоставляет **номер И наименование
одновременно** — цена проставляется только когда оба совпали; иначе позиция
остаётся без цены (честно, а не «примерно»). Подробности и цифры —
`references/troubleshooting.md` в навыке `parts-catalog-digitizer`
(`~/.claude/skills/parts-catalog-digitizer/`).

## Команды

```bash
python3 tools/build_catalog.py --list            # что уже собрано
python3 tools/build_catalog.py --remove ID       # удалить оборудование
python3 tools/build_catalog.py file.pdf --force  # пересобрать принудительно
```

Опции: `--dpi 120` `--quality 68` (размер/чёткость чертежей),
`--format auto|toc|headings` (формат каталога, обычно определяется сам),
`-o папка` (куда собирать, по умолчанию `catalog_book`).

## Поддерживаемые форматы PDF

| Формат | Признаки | Пример |
|---|---|---|
| `toc` | оглавление с номерами узлов, колонтитулы «Стр. N», чертёж перед таблицей | каталоги КМЗ (БС-215, БС-230) |
| `headings` | заголовок узла на странице, таблица под чертежом | Weichai WP17 |

Шаблон номера детали и порядок колонок (имя↔кол-во) определяются автоматически
по статистике документа. Для нестандартного PDF смотрите отчёт сборки в консоли —
он показывает, что именно распознано.

## Возможности просмотрщика (catalog_book/index.html)

- вкладки оборудования, список узлов с фильтром;
- сквозной поиск по номеру/наименованию → переход на лист + подсветка позиции (Enter — первый результат);
- зум чертежа: колесо/кнопки, панорама перетаскиванием; карусель, если у листа
  несколько изображений («Рисунок N/M», листается стрелками);
- клик по номеру — копирование в буфер; ⬇ CSV — спецификация узла файлом;
- цена (руб.) в таблице, если найдена в прайс-листе (`tools/apply_prices.py`);
- **заказ**: в каждой строке — поле «Нужно» (по умолчанию = кол-во в сборке) и
  кнопка ➕; заказ копится по всему каталогу и переживает перезагрузку страницы.
  В панели заказа — количество (+/− или вручную), сумма по каждой позиции и
  итог, переход обратно к детали в каталоге, экспорт в CSV/Excel (.xls) или
  копирование текстом — готово отправить снабжению;
- «⬇ Экспорт всех номеров (Excel)» в сайдбаре — выгрузка всех уникальных
  номеров каталога с ценой и привязкой к оборудованию/узлам;
- ссылки на конкретный узел (`index.html#e=bs215&u=12`) — можно отправить коллеге;
- клавиатура: `/` — поиск, `c` — заказ, ← → — узлы, Esc — закрыть; светлая/тёмная тема;
- работает офлайн, адаптивен (телефон/планшет), печатается.
- верхний баннер с контактом по вопросам каталога (текст — в `viewer.html`,
  переменные `CONTACT_NAME`/`CONTACT_EMAIL`).

## Структура

```
tools/build_catalog.py    генератор (парсинг PDF → data.js + img/ → самодостаточный index.html)
tools/pack_standalone.py  встраивает чертежи в index.html (вызывается build_catalog.py сам)
tools/viewer.html         шаблон интерфейса
catalog_book/
  index.html             готовый просмотрщик — САМОДОСТАТОЧНЫЙ, это и есть коммитимый файл
  data.js                данные + img/ — рабочий кэш сборки, в git не хранится
  img/                   чертежи JPEG — рабочий кэш сборки, в git не хранится
  .build/                манифест и кэш SHA1, в git не хранится
```

`catalog_book/index.html` — единственный файл из этой папки, который лежит в
git (~90 МБ; растёт с каждым добавленным каталогом). Всё остальное — рабочие
файлы генератора, воспроизводимые из исходных PDF в любой момент.

Полностью восстановить рабочий кэш (`data.js`+`img/`) из исходных PDF этого репозитория:

```bash
python3 tools/build_catalog.py "БС-215+Каталог+запчастей.zip.001" --id bs215 --label "БС-215"
python3 tools/build_catalog.py "БС-230.00.00.000 РЭ2 Каталог запчастей.zip.001" --id bs230 --label "БС-230"
python3 tools/build_catalog.py "Каталог запчастей WP17 итог.pdf" --id wp17 --label "WP17"
```

## Прочие файлы

- `catalog_parts_list.csv / .md / .html` — плоский перечень всех идентификационных
  номеров с привязкой к оборудованию и узлам (для Excel / чтения / поиска);
- `Каталог_идентификационные_номера.xlsx` — то же в Excel с листами по машинам.
