# KMZ-Parts_book

Заводские каталоги запасных частей и **генератор интерактивных каталогов** из PDF.
Брендировано под АО «Развитие» (контрагент АО «Копейский машзавод» по этим
каталогам) — цвета/лого в `tools/viewer.html`, легко перебрендировать под
другую компанию (см. CSS-переменные в начале файла).

Из PDF-каталога (страницы «чертёж + таблица спецификации») собирается офлайн-сайт:
чертежи рядом со спецификациями (№ · Номер детали · Наименование · Цена ·
Кол-во · Нужно), сквозной поиск детали, зум чертежей (карусель для листов с
несколькими изображениями), заказ с ценами и итоговой суммой, экспорт в CSV/Excel.

**`catalog_book/index.html` — единственный файл, полностью самодостаточный**
(все чертежи встроены внутрь как data:-URI). Открывается двойным кликом в
любом браузере после простого `git clone`/скачивания репозитория с GitHub —
никаких соседних папок, никакого Python на стороне читателя. Python нужен
только для *сборки* каталога из PDF.

## Два каталога в этом репозитории

| | Что это | Чем открывается |
|---|---|---|
| **Единый каталог** (корень репозитория) | Сайт в общем стиле с каталогами **Cummins** и **NHL**: экран выбора моделей, карточка детали, проверка списка номеров, заказ-спецификация, светлая и тёмная тема. Данные — статические файлы, без сборки | `index.html`, публикуется на Vercel |
| **catalog_book/index.html** | Прежний самодостаточный просмотрщик, собираемый из PDF (~95 МБ, чертежи внутри файла) | двойной клик, работает офлайн без сервера |

Оба берут данные из одних и тех же исходных PDF. Прежний просмотрщик оставлен
как есть — он удобен, когда нужно отдать каталог одним файлом без сайта.

**Документы подключены к единому каталогу.** В шапке — кнопка
**«📖 Документы»**, она открывает панель со всеми материалами выбранной машины;
та же ссылка стоит в шапке каждого раздела и на карточке машины на экране
выбора моделей. Ссылки ведут точно в нужный документ:

| Машина | Что подключено |
|---|---|
| **БС-215** | Технические характеристики, РЭ2, РЭ3, РЭ4, Инструкция от 22.09.2020 (`Руководства.html#doc=<id>`) и офлайн-просмотрщик (`index.html#e=bs215`) |
| **БС-230** | офлайн-просмотрщик (`index.html#e=bs230`) |
| **WP17** | офлайн-просмотрщик (`index.html#e=wp17`) |

Руководств по БС-230 и WP17 в репозитории нет — подключать нечего. Как только
их PDF появятся, соберите их в читатель (`python3 tools/build_docs.py …`) и
добавьте ссылки в `docs` соответствующей машины в `build/machines.json`.

**Поиск узла в тексте руководств.** В шапке раздела рядом с «Документами» есть
ссылка **«🔎 Найти узел в руководствах»**: она открывает читатель с уже
выполненным поиском по названию узла и переходит на первую найденную страницу.
Запрос строится из самого длинного буквенного слова названия с отброшенным
окончанием («Установка водяного пылеподавления» → `пылеподавлен`), чтобы
находились и другие падежи. По разделам БС-215 и БС-230 такой запрос находит
страницы в 89–90 % случаев; остальные слова («Гидропульт», «Гидроразводка»)
в тексте руководств просто не встречаются — читатель откроется с этим запросом
в поле поиска, его можно поправить руками.

## Единый каталог: что внутри

Оборудование каталога:

| Машина | Разделов | Позиций с номером | Уник. номеров | Чертежей | Цены из прайса |
|---|---|---|---|---|---|
| **БС-215** — станок буровой самоходный БАРС | 54 | 1823 | 1249 | 296 | 934 (75 %) |
| **БС-230** — станок буровой | 60 | 1827 | 1247 | 301 | 702 (56 %) |
| **WP17** — двигатель Weichai | 73 | 629 | 541 | 89 | — |

У WP17 цен нет: в каталоге двигателя номера Weichai (8–13 знаков), а прайс
КМЗ ведётся по номенклатурным номерам (18 знаков) — пересечения нет ни по
одному номеру. Это свойство данных, а не ошибка сопоставления.

Возможности — те же, что в каталогах Cummins и NHL:

- **экран «Выбор моделей»** с счётчиком наполнения и документами каждой машины;
- **📖 Документы** — панель с руководствами и офлайн-просмотрщиком машины
  (см. таблицу выше);
- **поиск** по номеру детали и наименованию (в том числе по русскому
  наименованию из прайса) в каталоге выбранной машины;
- **карточка детали** по клику на номер: наименования, цена, группа,
  и **«Где применяется»** — все разделы **всех машин**, где встречается номер
  (например, номер `068000001100000001` есть и у БС-215, и у БС-230);
- **🔎 Проверить список** — проверка списка номеров сразу по всем машинам:
  что есть в каталоге и где, чего нет, и какие номера каталога отсутствуют
  в вашем списке; результат выгружается в Excel;
- **заказ-спецификация** с количеством, ценами, экспортом в Excel и печатью;
- **💲 Обновить цены** — загрузка прайса из файла прямо в браузере;
- **⬇ Экспорт всех номеров со всеми атрибутами (Excel)** по всем машинам;
- светлая и **тёмная тема**; чертежи в тёмной теме остаются на белой подложке.

### Сборка данных единого каталога

```bash
# 1. восстановить рабочий кэш генератора из исходных PDF (нужен pymupdf)
python3 tools/build_catalog.py "БС-215+Каталог+запчастей.zip.001" --id bs215 --label "БС-215" --no-embed
python3 tools/build_catalog.py "БС-230.00.00.000 РЭ2 Каталог запчастей.zip.001" --id bs230 --label "БС-230" --no-embed
python3 tools/build_catalog.py "Каталог запчастей WP17 итог.pdf" --id wp17 --label "WP17" --no-embed

# 2. перенести состав и чертежи в формат единого каталога
node build/import_catalog_book.js      # -> bs215/ bs230/ wp17/ (data/parts.js + drawings/)

# 3. подставить цены и собрать данные сайта
node build/gen_data.js                 # -> data/app.js, data/catalogs.js, data/prices.js
```

`--no-embed` на шаге 1 обязателен: он оставляет чертежи отдельными файлами в
`catalog_book/img/`, откуда их забирает импорт. Пересобирать
`catalog_book/index.html` для распространения нужно **без** этого флага.

Прайсы указываются явно в `build/machines.json` (в корне лежат и другие
`.xlsx` — выгрузки номеров, их брать не надо):

- `priceCurrent` — действующий прайс, столбец **«Текущий»**;
- `priceAgreed` — прайс на согласование, столбец **«Несогласованный»**.

Сейчас задан только `priceCurrent` — `Прайс-лист 28.07.2026.xlsx`. Пустой
столбец цен в таблице не показывается. Заказ считается по «Несогласованному»,
а если такой цены нет — по «Текущему», с пометкой **тек.** в корзине.

Там же, в `build/machines.json`, описывается парк: `id` (он же имя подпапки),
`name`, `subtitle`, `currency` и `docs` — список документов машины:

```json
"docs": [
  { "url": "catalog_book/Руководства.html#doc=re4rukovod",
    "label": "РЭ4 — Руководство по эксплуатации",
    "kind": "Руководство",
    "src": "БС-215.00.00.000-01 РЭ4.pdf" },
  { "url": "catalog_book/index.html#e=bs215",
    "label": "Каталог запчастей одним файлом (офлайн-просмотрщик)",
    "kind": "Каталог", "src": "catalog_book/index.html" }
]
```

`kind` задаёт группу в панели («Руководство» / «Каталог»), `src` — подпись с
исходным файлом. Идентификаторы документов (`#doc=…`) видны в адресной строке
читателя при переключении вкладок.

### Публикация единого каталога на Vercel

Framework preset **Other**, Build Command пусто, Root Directory — **корень
репозитория**. Весь сайт закрыт серверным входом (`middleware.js`, `api/`,
`auth/`).

> **Учётки не заведены.** Пока список в `auth/accounts.mjs` пуст, вход **не
> включается** и сайт отдаётся всем — иначе свежий деплой нельзя было бы
> открыть. Перед боевым запуском заведите владельца:
> `node build/make_user.mjs set <логин> <пароль> --role permanent --name "Имя"`,
> и задайте `AUTH_SECRET` в переменных окружения Vercel
> (`node build/make_user.mjs secret`).

## Генератор catalog_book (прежний просмотрщик)

Всё, что ниже, относится к прежнему самодостаточному просмотрщику и к разбору
исходных PDF. Единый каталог использует тот же разбор — через
`build/import_catalog_book.js`.

### Быстрый старт (сборка/добавление каталога)

```bash
pip install pymupdf

# добавить каталог (PDF, ZIP или разбитый ZIP.001 — части найдутся сами)
python3 tools/build_catalog.py "Новый каталог.pdf" --id new1 --label "НОВЫЙ" \
        --title "Полное название оборудования" --sub "Обозначение документа"

# результат: catalog_book/index.html — сразу самодостаточный, готов к раздаче
```

Повторный запуск с новым файлом **добавляет** его к уже собранному каталогу.
Неизменённые источники пропускаются по кэшу (SHA1), пересборка — мгновенная.
Чертежи встраиваются в `index.html` автоматически при каждой сборке — не
нужно помнить про отдельный шаг «упаковки», результат всегда готов к commit/раздаче.

Для быстрой локальной разработки (когда чертежей много и не хочется ждать
base64-кодирование при каждом запуске) есть флаг `--no-embed`: `index.html`
тогда лишь ссылается на `data.js`/`img/` рядом — такой файл **не для
распространения**, перед коммитом/отправкой пересоберите без флага.

### Прайс-лист (цены в каталоге)

```bash
python3 tools/apply_prices.py "Прайс-лист.xlsx"   # вписывает цены в кэш .build/*.json
python3 tools/build_catalog.py "<тот же PDF>" --id <тот же id>  # кэш-хит, пересобрать index.html с ценами
```

Номера деталей у КМЗ — 17-18-значные; Excel хранит числа с точностью ~15-16
значащих цифр, поэтому колонка «Номенклатурный номер» в прайс-листе **уже
теряет точность в самом файле** (проверяется по сырому XML, не чинится
перепарсингом). Слепое сопоставление по округлённому числу даёт ~79% ложных
совпадений. `apply_prices.py` поэтому сопоставляет **номер И наименование
одновременно** — цена проставляется только когда оба совпали; иначе позиция
остаётся без цены (честно, а не «примерно»). Подробности и цифры —
`references/troubleshooting.md` в навыке `parts-catalog-digitizer`
(`~/.claude/skills/parts-catalog-digitizer/`).

Актуальный прайс (`Прайс-лист 28.07.2026.xlsx`) хранит номенклатурный номер
полным ТЕКСТОМ — тогда `apply_prices.py` сопоставляет **точно по номеру**
(без угадывания). Сейчас цена проставлена у 2681 строки каталога (2610 — точно
по номеру). `tools/export_numbers_with_prices.py` выгружает все номера с ценами
в `Каталог_номера_с_ценами.xlsx` (номера — текстом, Excel не испортит).

### Руководства по эксплуатации (📖)

Руководства (РЭ2/РЭ3/РЭ4, теххарактеристики, инструкции) встраиваются в
**отдельный самодостаточный «читатель»** `catalog_book/Руководства.html`,
связанный с каталогом кнопкой «📖 Руководства» (и ссылкой «‹ К каталогу»
обратно). Отдельным файлом — потому что вместе с парт-каталогом (~90 МБ) они
превысили бы лимит GitHub 100 МБ.

```bash
python3 tools/build_docs.py \
    "4 Технические характеристики бурового станка БС 215.pdf::Технические характеристики БС-215" \
    "БС-215.00.00.000-01 РЭ2-1-17.pdf::РЭ2 — Руководство по эксплуатации" \
    "БС-215.00.00.000-01 РЭ3.zip.001::РЭ3 — Руководство по эксплуатации" \
    "БС-215.00.00.000-01 РЭ4.pdf::РЭ4 — Руководство по эксплуатации" \
    "БС-215_22.09.2020_003.pdf::Инструкция (22.09.2020)"
python3 tools/pack_docs.py -o "catalog_book/Руководства.html"   # самодостаточный файл
```

Читатель: вкладки документов, автособранное оглавление, **сквозной поиск по
всему тексту** руководств с переходом на страницу, зум страниц, тёмная/светлая
тема, офлайн. Вход — PDF, ZIP или разбитый `.zip.001`; заголовок задаётся через
`путь::Заголовок`.

Ссылки в читатель понимают три параметра:

| Параметр | Что делает |
|---|---|
| `#doc=<id>` | открыть это руководство (`tehnichesk`, `re2rukovod`, `re3rukovod`, `re4rukovod`, `instrukciy`) |
| `&page=<N>` | на этой странице |
| `&q=<запрос>` | сразу выполнить поиск по тексту всех руководств; если `doc` не задан — перейти на первую найденную страницу |

Пример: `Руководства.html#q=пылеподавлен` — открыть руководства и найти узел.
Текущий адрес читатель держит в хеше, поэтому любую страницу с найденным
запросом можно скопировать и отправить коллеге.

В боковой панели читателя две ссылки возврата: **«‹ К единому каталогу»**
(`../index.html`) и **«‹ Каталог одним файлом»** (`index.html`).
Рабочий кэш `docs.js`+`docs_img/` в git не хранится (воспроизводится из PDF);
коммитится только самодостаточный `Руководства.html`.

### Команды

```bash
python3 tools/build_catalog.py --list            # что уже собрано
python3 tools/build_catalog.py --remove ID       # удалить оборудование
python3 tools/build_catalog.py file.pdf --force  # пересобрать принудительно
```

Опции: `--dpi 120` `--quality 68` (размер/чёткость чертежей),
`--format auto|toc|headings` (формат каталога, обычно определяется сам),
`-o папка` (куда собирать, по умолчанию `catalog_book`).

### Поддерживаемые форматы PDF

| Формат | Признаки | Пример |
|---|---|---|
| `toc` | оглавление с номерами узлов, колонтитулы «Стр. N», чертёж перед таблицей | каталоги КМЗ (БС-215, БС-230) |
| `headings` | заголовок узла на странице, таблица под чертежом | Weichai WP17 |

Шаблон номера детали и порядок колонок (имя↔кол-во) определяются автоматически
по статистике документа. Для нестандартного PDF смотрите отчёт сборки в консоли —
он показывает, что именно распознано.

### Возможности просмотрщика (catalog_book/index.html)

- вкладки оборудования, список узлов с фильтром;
- сквозной поиск по номеру/наименованию → переход на лист + подсветка позиции (Enter — первый результат);
- зум чертежа: колесо/кнопки, панорама перетаскиванием; карусель, если у листа
  несколько изображений («Рисунок N/M», листается стрелками);
- клик по номеру — копирование в буфер; ⬇ CSV — спецификация узла файлом;
- цена (руб.) в таблице, если найдена в прайс-листе (`tools/apply_prices.py`);
- **заказ**: в каждой строке — поле «Нужно» (по умолчанию = кол-во в сборке) и
  кнопка ➕; заказ копится по всему каталогу и переживает перезагрузку страницы.
  В панели заказа — количество (+/− или вручную), сумма по каждой позиции и
  итог, переход обратно к детали в каталоге, экспорт в CSV/Excel (.xls) или
  копирование текстом — готово отправить снабжению;
- «⬇ Экспорт всех номеров (Excel)» в сайдбаре — выгрузка всех уникальных
  номеров каталога с ценой и привязкой к оборудованию/узлам;
- ссылки на конкретный узел (`index.html#e=bs215&u=12`) — можно отправить коллеге;
- клавиатура: `/` — поиск, `c` — заказ, ← → — узлы, Esc — закрыть; светлая/тёмная тема;
- работает офлайн, адаптивен (телефон/планшет), печатается.
- верхний баннер с контактом по вопросам каталога (текст — в `viewer.html`,
  переменные `CONTACT_NAME`/`CONTACT_EMAIL`).

## Структура

```
index.html app.js styles.css unified.css   единый каталог (сайт в стиле Cummins/NHL)
data/app.js               window.APP       — брендинг и ключи хранилища
data/catalogs.js          window.MACHINES + window.CATALOGS
data/prices.js            window.PRICES_BY — цены по машинам
data/part_info.js         window.PART_INFO — фото и характеристики для карточки
bs215/ bs230/ wp17/       data/parts.js + drawings/ каждой машины
build/machines.json       описание парка и прайсов (правится руками)
build/import_catalog_book.js  catalog_book/data.js -> <машина>/data/parts.js + чертежи
build/import_xlsx.js      импорт состава машины из таблицы Excel (для машин без PDF)
build/gen_data.js         сборка data/*.js из подпапок машин и прайсов
middleware.js api/ auth/ login.html        вход по логину и паролю

tools/build_catalog.py    генератор (парсинг PDF → data.js + img/ → самодостаточный index.html)
tools/pack_standalone.py  встраивает чертежи в index.html (вызывается build_catalog.py сам)
tools/viewer.html         шаблон интерфейса
catalog_book/
  index.html             готовый просмотрщик — САМОДОСТАТОЧНЫЙ, это и есть коммитимый файл
  data.js                данные + img/ — рабочий кэш сборки, в git не хранится
  img/                   чертежи JPEG — рабочий кэш сборки, в git не хранится
  .build/                манифест и кэш SHA1, в git не хранится
```

`catalog_book/index.html` — единственный файл из этой папки, который лежит в
git (~90 МБ; растёт с каждым добавленным каталогом). Всё остальное — рабочие
файлы генератора, воспроизводимые из исходных PDF в любой момент.

Полностью восстановить рабочий кэш (`data.js`+`img/`) из исходных PDF этого репозитория:
